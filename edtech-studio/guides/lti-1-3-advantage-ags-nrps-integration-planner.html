Three Production Traps in LTI 1.3 Advantage Deployments

  • Composite Tenant Lookup: Canvas Cloud shares a single iss (https://canvas.instructure.com) across universities—always key tenants by iss + client_id + deployment_id.
  • Third-Party Cookie Blocking in Iframes: Safari ITP and Chrome iframe policies drop unpartitioned session cookies; use LTI Platform Storage (postMessage) or SameSite=None; Secure; Partitioned state validation.
  • Publish a Public JWKS URL, Not Static PEM Files: University LMS admins paste PEM keys manually far slower than registering a live /.well-known/jwks.json endpoint with kid rotation.

Technical Drill-Down 01 — 4-Step LTI 1.3 OIDC Launch Sequence 
1. LMS -> Tool /oidc/init:    GET/POST iss, login_hint, target_link_uri, lti_message_hint, client_id
2. Tool -> LMS Auth Endpoint: Redirect with state, nonce, response_mode=form_post, prompt=none, scope=openid
3. LMS -> Tool /lti/launch:   POST signed id_token (RS256 JWT) containing roles, context, and AGS endpoints
4. Tool Verification:         Verify JWT signature via LMS JWKS, check aud/iss/exp, consume single-use nonce
