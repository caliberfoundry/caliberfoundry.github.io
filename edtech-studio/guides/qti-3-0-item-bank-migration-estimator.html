Key Architectural Shifts in 1EdTech QTI 3.0

  • Hyphenated HTML5-Friendly Tags: QTI 3.0 replaces QTI 2.1 camelCase (assessmentItem, choiceInteraction) with web-component-aligned kebab-case (qti-assessment-item, qti-choice-interaction).
  • Built-In Accessibility Catalogs: QTI 3.0 embeds spoken/braille/sign-language Personal Needs & Preferences (qti-companion-materials-info and accessibility catalogs) directly per token.
  • Deterministic Response Processing: Standard match_correct and map_response templates ensure identical scoring across delivery engines without executing untrusted script code.

Technical Drill-Down 01 — Minimal Valid QTI 3.0 Choice Item Skeleton 
<qti-assessment-item xmlns="http://www.imsglobal.org/xsd/imsqtiasi_v3p0"
  identifier="item-webhook-idempotency" title="Idempotent Webhook Retry" adaptive="false" time-dependent="false">
  <qti-response-declaration identifier="RESPONSE" cardinality="single" base-type="identifier">
    <qti-correct-response><qti-value>CHOICE_B</qti-value></qti-correct-response>
  </qti-response-declaration>
  <qti-outcome-declaration identifier="SCORE" cardinality="single" base-type="float"/>
  <qti-item-body>
    <qti-choice-interaction response-identifier="RESPONSE" max-choices="1">
      <qti-prompt>How should a webhook consumer handle duplicate event_id deliveries?</qti-prompt>
      <qti-simple-choice identifier="CHOICE_A">Return HTTP 500 to stop retries</qti-simple-choice>
      <qti-simple-choice identifier="CHOICE_B">Deduplicate on event_id and return HTTP 200</qti-simple-choice>
    </qti-choice-interaction>
  </qti-item-body>
  <qti-response-processing template="https://purl.imsglobal.org/spec/qti/v3p0/rptemplates/match_correct.xml"/>
</qti-assessment-item>
