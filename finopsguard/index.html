CSV format and comparison rules

Use the same task IDs in both variants and record every attempt, including failures. Use pseudonyms for tasks and actors. One row represents one execution, retry, review, or final outcome. Download a worked CSV template.

variant, task_id, call_id, stage, actor
Use before or after. Give every call a unique ID within the variant. Use execute, retry or review for calls. The independent reviewer must have a different actor ID from the workers. Use separate task IDs for separate deliverables.
cost_basis, cost_usd
Use billed for an attributable USD charge, estimated for a rate-card estimate, no_charge for a verified zero LLM fee, or subscription or unknown with a blank cost. An optional estimated_usd column can record a separate rate-card equivalent. Use identical pricing assumptions for both variants.
verdict, rubric, expected_calls
Close each task with one outcome row. Leave its call ID and charges blank. Enter accepted, rejected or pending, the rubric version, and the total number of execution, retry and review rows. The outcome actor identifies the independent reviewer.
input_tokens, output_tokens, cached_input_tokens
Enter metered input and output to compare token usage. Input includes cached reads. Add cached input where available to show the fresh and cached split. Use explicit zeros only when known. The template uses dataset=example. Omit that marker for your own measured runs.

Both cohorts must include the same tasks and rubric. Every baseline acceptance must still pass. Unit cost includes the spend on rejected tasks. The observed difference describes only the supplied cohort. Missing prices, usage or verdicts remain unknown.
